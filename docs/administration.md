# Руководство администратора

[BardForge Foundry](../README.md) → Администрирование

**Эксперимент: реальная сессия Foundry/удалённый TURN не проверены. В Studio нет готовой панели отправителя.** Приёмник рассчитан на API Foundry 13+, но манифест не содержит неподтверждённой отметки verified. Установка ZIP сама по себе не создаёт источник звука.

Для проверки нужны: тестовый мир Foundry, отдельно подготовленный отправитель живого MediaStream, relay, браузер игрока и при необходимости TURN. Сначала ознакомьтесь с [ограничениями проверки](https://github.com/BardForge/bardforge-foundry/issues/3). Не используйте рабочую сессию как первый тест.

## Собрать и установить приёмник

На Windows с Windows PowerShell:

```powershell
npm run package:module
```

Получится `dist/bardforge-receiver-0.1.0.zip`. Скрипт проверяет состав архива и манифест. В ZIP входят приёмник, README, LICENSE, границы лицензии, сторонние уведомления и CHANGELOG; relay, SDK, зависимости, ключи и тестовые данные не включены. До сборки установите зависимости по руководству разработчика.

Для ручной установки распакуйте папку `bardforge-receiver` в `Data/modules/` каталога данных Foundry, перезапустите Foundry и включите модуль в нужном мире. В настройках модуля укажите WSS-адрес, комнату и **ключ слушателя**. Для соединения через интернет обычно нужен TURN. Каждый игрок сам нажимает «Включить звук» и регулирует свою громкость. Установка в реальный мир требует решения его администратора; команды сборки её не выполняют.

## Relay и ключи

Локальный запуск из корня репозитория в PowerShell:

```powershell
$env:BARDFORGE_ROOM = 'my-table'
$env:BARDFORGE_PUBLISH_TOKEN = node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
$env:BARDFORGE_LISTEN_TOKEN = node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
node services/relay/server.mjs
```

Локальный адрес — `ws://127.0.0.1:8787/relay`. Он подходит только для браузера на том же компьютере. Ключи должны различаться и содержать 32–256 символов; передавайте игрокам только ключ слушателя. Не сохраняйте рабочие ключи в репозитории, логах и URL.

| Переменная                | Значение по умолчанию                                                 |
| ------------------------- | --------------------------------------------------------------------- |
| `BARDFORGE_ROOM`          | Обязательная комната: латиница, цифры, `_`, `-`, до 64 символов       |
| `BARDFORGE_PUBLISH_TOKEN` | Обязательный случайный ключ отправителя                               |
| `BARDFORGE_LISTEN_TOKEN`  | Обязательный отдельный случайный ключ слушателей                      |
| `HOST`                    | `127.0.0.1`                                                           |
| `PORT`                    | `8787`                                                                |
| `BARDFORGE_MAX_LISTENERS` | `16`, допустимо 1–64                                                  |
| `BARDFORGE_ORIGINS`       | Не задан; при необходимости — точные разрешённые Origin через запятую |

Для удалённого использования разверните relay за HTTPS reverse proxy с действующим сертификатом и поддержкой WebSocket Upgrade. Оставьте Node-сервис на loopback, наружу откройте HTTPS. Путь подключения — `wss://имя-сервера/relay`; `/health` сообщает только доступность сервиса. Например, [Caddy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy) может проксировать публичное имя на `127.0.0.1:8787`. Клиент отвергает незашифрованный `ws:` вне loopback.

TURN разворачивается и оплачивается отдельно: WSS relay не пересылает аудио через NAT. Настройте TURN-адрес и временные/ограниченные учётные данные на обеих сторонах. STUN не гарантирует соединение через любой NAT. Режим «Только через TURN» исключает прямое соединение и требует рабочего TURN. Без него прямые WebRTC-соединения могут раскрывать сетевые адреса участникам.

Origin allowlist дополняет ключи, но не заменяет их. Пустой список разрешает попытку авторизации с любого Origin. При включении списка проверьте фактический Origin хост-приложения и добавьте Origin Foundry. Ключ слушателя и параметры TURN хранятся в настройках мира и доступны его пользователям; ключ отправителя туда вводить нельзя. Для смены ключей обновите окружение relay, перезапустите его и обновите разрешённые клиенты.

Ограничения: авторизация за 5 секунд, входящие сообщения до 64 KiB, 256 сообщений за 10 секунд на соединение, отключение при исходящем буфере свыше 256 KiB, ограничение числа соединений, heartbeat каждые 15 секунд. Бинарные сообщения отвергаются. Звуковой буфер управляется WebRTC, очереди аудиофайлов на сервере нет. Неуспешное согласование ограничено 30 секундами; сбой слушателя не должен прерывать здоровые соединения отправителя.

## Проверить соединение

После включения модуля и авторизации отправителя каждый игрок нажимает «Включить звук». Проверьте слышимый звук, личную громкость, остановку отправителя и повторное подключение после разрыва сети. Статус relay или успешное WebSocket-соединение не доказывают передачу аудио. При сбое проверьте комнату, разные ключи ролей, HTTPS/WSS, Origin и TURN на обеих сторонах; не публикуйте ключи и адреса частной инфраструктуры в отчёте.

Локальный браузерный тест в CI не подтверждает перечисленные проверки на вашем хостинге. Для изменения SDK и запуска тестов используйте [руководство разработчика](development.md).
