# BardForge Foundry

Отдельное экспериментальное дополнение: приёмник звука для Foundry VTT, браузерный SDK отправителя и сервер сигнализации WebRTC. Репозиторий не содержит основное приложение BardForge Studio и не переносит его историю.

## AI-Assisted Development

BardForge is developed with assistance from artificial intelligence tools. AI may contribute to code, documentation, testing, and technical design. All contributions remain subject to human review, validation, and applicable licensing requirements.

**Это не готовая интеграция с настольным Studio.** В базовом приложении нет панели отправителя; установка ZIP приёмника не добавляет её. SDK принимает настоящий аудиопоток `MediaStream`, который должна предоставить отдельная интеграция. React-панель из основного проекта сюда не включена: она не является самостоятельным приложением.

Приёмник рассчитан на документированные API Foundry 13+. В манифесте задано только `minimum: 13`, без фиктивной отметки `verified`. Работа в реальном мире Foundry, с конкретными системами/модулями, публичным TLS и удалённым TURN **пока не проверена**. Автоматические тесты проверяют реальный обмен звуком между браузерными контекстами на одном компьютере; они не подменяют проверку Foundry.

## Что здесь находится

| Путь                                  | Назначение                                                                 |
| ------------------------------------- | -------------------------------------------------------------------------- |
| `modules/foundry/bardforge-receiver/` | Устанавливаемый приёмник: кнопка включения, личная громкость, RU/EN        |
| `services/relay/`                     | Отдельный Node-сервис авторизации и сигнализации                           |
| `sdk/`                                | Публичный вход браузерного SDK, без React и без зависимости от ядра Studio |
| `tests/`                              | Проверки протокола, ограничений и настоящего звука через WebRTC            |
| `scripts/package-module.ps1`          | Сборка и проверка ZIP приёмника из явного списка файлов                    |

Звук передаётся через зашифрованный WebRTC напрямую между отправителем и игроком либо через отдельный TURN-сервер. Relay пересылает только SDP/ICE и не хранит аудио. На каждого слушателя создаётся отдельное соединение; отправителю нужна соответствующая исходящая полоса. По умолчанию разрешены один отправитель и 16 слушателей.

## Установка зависимостей и проверки

Нужен **Node.js 24**. Версии Playwright и `ws` взяты из lock-файлов исходного проекта; зависимости ядра Studio не требуются.

```powershell
npm ci
npm ci --prefix services/relay
npx playwright install chromium
npm run lint
npm run format:check
npm run check:public
npm test
npm run test:browser
```

`npm test` проверяет авторизацию и разделение ролей, маршрутизацию, лимиты, таймауты и изоляцию сбоя одного слушателя, а также комплектность модуля. `npm run test:browser` запускает один Chromium с двумя изолированными контекстами, создаёт тон в Web Audio и проверяет Opus RTP, ненулевую декодированную волну, личную громкость, восстановление после перезапуска relay и прекращение звука после остановки отправителя. Реальный микрофон и пользовательские аудиофайлы не нужны.

Браузерный тест не запускает Foundry и не меняет мир пользователя. Случайные ключи существуют только во время теста. Для ручной проверки сервера отдельно достаточно `npm ci --prefix services/relay`; Playwright нужен только для тестов.

CI выполняет эти же проверки на Windows с Node 24, затем собирает ZIP. GitHub Actions закреплены по SHA; у workflow только `contents: read`. Публикации релизов, деплоя, подписи и установки в пользовательский Foundry нет.

`npm run format` применяет форматирование. `check:public` проверяет отслеживаемые и ещё не добавленные публичные файлы, исключённые через `.gitignore` результаты сборки и зависимости в проверку не входят. Это проверка запрещённых путей и известных форматов секретов, а не универсальный поиск любых конфиденциальных данных. Перед публикацией также нужен просмотр diff. Лицензии зависимостей описаны в [THIRD_PARTY.md](THIRD_PARTY.md), изменения — в [CHANGELOG.md](CHANGELOG.md).

## ZIP приёмника

На Windows с Windows PowerShell:

```powershell
npm run package:module
```

Получится `dist/bardforge-receiver-0.1.0.zip`. Скрипт проверяет состав архива и манифест. В ZIP входят только папка приёмника и этот README, без relay, SDK, зависимостей, ключей и тестовых данных.

Для ручной установки распакуйте папку `bardforge-receiver` в `Data/modules/` каталога данных Foundry, перезапустите Foundry и включите модуль в нужном мире. В настройках модуля укажите WSS-адрес, комнату и **ключ слушателя**. Для соединения через интернет обычно нужен TURN. Каждый игрок сам нажимает «Включить звук» и регулирует свою громкость. Установка в реальный мир требует решения его администратора; команды сборки её не выполняют.

## Relay и ключи

Локальный запуск из корня репозитория в PowerShell:

```powershell
$env:BARDFORGE_ROOM = 'my-table'
$env:BARDFORGE_PUBLISH_TOKEN = node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
$env:BARDFORGE_LISTEN_TOKEN = node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
node services/relay/server.mjs
```

Локальный адрес — `ws://127.0.0.1:8787/relay`. Он подходит только для браузера на том же компьютере. Ключи должны различаться и содержать 32–256 символов; передавайте игрокам только ключ слушателя. Не сохраняйте рабочие ключи в репозитории, логах и URL.

| Переменная                | Значение по умолчанию                                                 |
| ------------------------- | --------------------------------------------------------------------- |
| `BARDFORGE_ROOM`          | Обязательная комната: латиница, цифры, `_`, `-`, до 64 символов       |
| `BARDFORGE_PUBLISH_TOKEN` | Обязательный случайный ключ отправителя                               |
| `BARDFORGE_LISTEN_TOKEN`  | Обязательный отдельный случайный ключ слушателей                      |
| `HOST`                    | `127.0.0.1`                                                           |
| `PORT`                    | `8787`                                                                |
| `BARDFORGE_MAX_LISTENERS` | `16`, допустимо 1–64                                                  |
| `BARDFORGE_ORIGINS`       | Не задан; при необходимости — точные разрешённые Origin через запятую |

Для удалённого использования разверните relay за HTTPS reverse proxy с действующим сертификатом и поддержкой WebSocket Upgrade. Оставьте Node-сервис на loopback, наружу откройте HTTPS. Путь подключения — `wss://имя-сервера/relay`; `/health` сообщает только доступность сервиса. Например, [Caddy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy) может проксировать публичное имя на `127.0.0.1:8787`. Клиент отвергает незашифрованный `ws:` вне loopback.

TURN разворачивается и оплачивается отдельно: WSS relay не пересылает аудио через NAT. Настройте TURN-адрес и временные/ограниченные учётные данные на обеих сторонах. STUN не гарантирует соединение через любой NAT. Режим «Только через TURN» исключает прямое соединение и требует рабочего TURN. Без него прямые WebRTC-соединения могут раскрывать сетевые адреса участникам.

Origin allowlist дополняет ключи, но не заменяет их. Пустой список разрешает попытку авторизации с любого Origin. При включении списка проверьте фактический Origin хост-приложения и добавьте Origin Foundry. Ключ слушателя и параметры TURN хранятся в настройках мира и доступны его пользователям; ключ отправителя туда вводить нельзя. Для смены ключей обновите окружение relay, перезапустите его и обновите разрешённые клиенты.

Ограничения: авторизация за 5 секунд, входящие сообщения до 64 KiB, 256 сообщений за 10 секунд на соединение, отключение при исходящем буфере свыше 256 KiB, ограничение числа соединений, heartbeat каждые 15 секунд. Бинарные сообщения отвергаются. Звуковой буфер управляется WebRTC, очереди аудиофайлов на сервере нет. Неуспешное согласование ограничено 30 секундами; сбой слушателя не должен прерывать здоровые соединения отправителя.

## SDK отправителя

SDK предназначен для браузера в безопасном контексте. Хост должен предоставить живой аудио-`MediaStream`, например выход `AudioContext.createMediaStreamDestination()`. Разрешение воспроизведения, интерфейс, маршрутизация выбранных дорожек и хранение настроек остаются ответственностью интеграции.

```js
import { RelayAudioClient } from './sdk/index.js';

const publisher = new RelayAudioClient({
  role: 'publisher',
  url: relayUrl,
  room: roomName,
  token: publisherKey,
  stream: audioStream,
  iceServers: configuredIceServers,
  onState: ({ state, listeners }) => renderConnectionState(state, listeners),
});
publisher.start();
// При завершении сессии:
publisher.stop();
```

Переменные в примере предоставляет хост; это контракт интеграции, а не готовое приложение. `stop()` закрывает соединения, но не останавливает дорожки, принадлежащие микшеру. Тестовый отправитель с реальным тоном уже есть в `tests/transport.browser.mjs`.
